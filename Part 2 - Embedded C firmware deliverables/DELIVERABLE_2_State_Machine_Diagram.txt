================================================================================
                       WAKE-UP DECISION LOGIC
================================================================================

while (true) {
    current_time = RTC.getTime();
    motion_detected = (PA0_EXTI_FLAG == 1);
    time_since_fix = current_time - last_fix_time;
    
    CONDITION_1 = motion_detected;
    CONDITION_2 = (time_since_fix >= 1800);  // 30 minutes
    
    if (CONDITION_1 OR CONDITION_2) {
        WAKE_UP();
        transition_to(STATE_ACQUIRE_GPS);
    } else {
        SLEEP();  // Stays in STOP2 until next interrupt
    }
}

WAKE TRIGGERS:
  ✓ LIS2DH motion interrupt (PA0 EXTI0) = Immediate wake
  ✓ RTC alarm after 30 minutes = Scheduled wake
  ✓ No other wakes = Minimal power drain


================================================================================
                      TIMEOUT PROTECTION
================================================================================

STATE_ACQUIRE_GPS:
  GPS max wait: 30 seconds
  If no fix after 30s → Use last known position
  Prevents battery drain from searching for GPS

STATE_TRANSMIT_LORA:
  LoRa max transmit: 10 seconds (with retries)
  If TX fails after 10s → Abort and return to sleep
  Prevents stuck states

STATE_SLEEP:
  RTC will force wake every 30 minutes
  No infinite sleep without update


================================================================================
                     ENERGY OPTIMIZATION DECISIONS
================================================================================

1. MOTION-TRIGGERED (Fast Path):
   → Immediate GPS update when pet moves
   → Responsive tracking for active pets
   → Additional battery drain only on activity

2. PERIODIC BACKUP (30-minute):
   → Prevents "silent collar" periods
   → Guarantees location update even if stationary
   → Balances tracking latency vs. battery

3. GPS TIMEOUT (30 seconds):
   → Prevents GPS module from draining battery
   → Falls back to last known position if no fix
   → Acceptable latency for real-time tracking

4. DEEP SLEEP (STOP2, 12µA):
   → Lowest power mode with RTC running
   → Wakes on accelerometer or RTC alarm
   → ~99% of time in this mode

5. COMPACT PAYLOAD (10 bytes):
   → Minimal LoRa airtime (200ms vs 2+ seconds)
   → Lower TX power requirement
   → Fits in ISM band restrictions

6. SF9 SPREADING FACTOR:
   → Balance: 5-10 km range vs 200ms airtime
   → More efficient than SF12 (4+ seconds)
   → Acceptable for local tracking scenarios
